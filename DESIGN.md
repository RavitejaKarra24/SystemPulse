# SystemPulse interface direction

## Intent

A calm, glanceable native system monitor. The interface should explain what this Mac is doing without resembling a neon control room or making the user hunt through five pages.

## Evidence and inspiration

Mobbin's public homepage was inspected visually and through its public content. Its neutral canvas, bold clear hierarchy, restrained borders, pill navigation, and generous grouping are the inspiration—not a claim to reproduce its private app library. Competitor research and priorities are recorded in `ROADMAP.md`.

## Rules

- Keep the menu-bar popover; 420 pt wide, height constrained by the screen. Persistent header and navigation; content scrolls independently.
- Overview is the landing page. Real-value tiles open existing CPU, memory, network, disk and power pages. Numeric shortcuts remain 1–5; 0 returns to Overview.
- Native system typography. Strong title/value contrast, quieter captions. Monospaced digits for measurements, not whole paragraphs.
- Settings is a separate retained native window with a standard sidebar and grouped forms; discoverable by the header gear, context menu and ⌘,. Appearance/module changes apply live. Overview is always available; hidden modules have no shortcut or insight route.
- Menu-bar metric selection/order is independent of visible topic modules. Keep gauges bounded; numeric fixtures must fit compactly. Unavailable battery/disk/network values remain unknown. Network is aggregate and disk is home-volume capacity, regardless of page selection.
- Alerts are off by default, silent and explicitly authorized. Use real observation timestamps, sustained thresholds, cooldown and recovery; do not advance time using cached readings. Unavailable data does not prove recovery. Settings exposes permission and delivery errors. Numeric drafts save on submit/focus loss; reject invalid values with explicit range feedback and allow Escape cancellation. Brief opt-outs/edits invalidate earlier evidence and queued delivery, even when the final preference values match the previous sample. Evaluate source acquisition times against the current clock; sleep or blocked I/O must not complete an old sustained window. Sleep suspends monitoring and rejects old in-flight results; wake starts fresh rate/CPU baselines without clearing history or observed byte totals. Do not count unobserved suspended bytes, invent CPU interval evidence, or call sleep recovery. Preserve latched breaches/cooldown and show unavailable CPU/memory in current summaries and diagnostics when no valid reading exists. Terminal shutdown cannot be restarted by delayed wake/settings callbacks.
- Insights are read-only, bounded observations, not diagnoses or automatic optimizers. Show concise measurements first, with expandable threshold/provenance caveats. Filter hidden modules before applying the four-row budget; no blanket health claim for empty or missing data.
- Semantic macOS window/control surfaces and primary/secondary labels. Follow system light/dark appearance. No ambient glow, heavy shadows or forced midnight palette.
- Use blue/purple/teal/orange/green only for metric identity and measured state. Status always includes words/icons, not color alone.
- 20 pt outer margin, 14 pt section gaps, 12–16 pt card padding, 14 pt card corners. Align figures and descriptions; use thin neutral separators.
- Selection uses a raised neutral surface. Pointer hover, keyboard focus and VoiceOver labels must remain visible and meaningful. Shared plain-button controls observe native focus and draw noninteractive, accessibility-hidden outlines rather than introducing extra focus stops. Headings expose structure and decorative marks are hidden. Increase Contrast strengthens relevant borders/text; actual system-setting and assistive behavior needs human sign-off.
- Topic charts use actual-time 5m/1h/24h windows. Raw readings use thin lines with gaps; longer ranges use discrete sample-mean dots, with averages/peaks labelled as means. Hover and keyboard inspection expose timestamps. Freezing stores that chart's data and time anchor, never pauses telemetry. Process-detail charts retain sample-count mode.
- Network selection scopes only that page; Overview, menu bar and exported network metrics remain aggregate. Switching interfaces resets chart inspection/freeze and its selected-series history. No SSID or reachability claims.
- Volume selection changes capacity monitoring, not cleanup scope or all-device disk activity. Describe APFS reclaimable availability and non-additive capacity; never equate logical scan size with guaranteed recovery.
- Cleanup scans remain explicitly home-scoped. Show native Cancel while running and “Stopping scan” while a filesystem call finishes; do not allow overlapping rescans. Report stopped/unmeasured scans in words, preserve observed partial results as read-only, and disable every Trash entry point until a complete rescan. Show an unmeasured-location count rather than claiming inaccessible data is empty. Progress counts planned locations, not bytes or remaining time. No automatic scan, permission change or elevation.
- Cleanup selection is bounded to 50 non-overlapping current eligible home-cache roots, session-only. A retained native resizable review window itemizes each path, logical size and safety note; selecting or opening review never moves data. Require a separate final Trash confirmation; no destructive default Return shortcut. Single-item and batch authorizations are scan-bound and one-shot. New scans invalidate old reviews. Move sequentially off the main actor, revalidate each location, report moved/failed/not-attempted without promising reclaimed space, and require new review for retries. Stop/sleep finishes the current OS call and skips remaining work. Normal Quit drains it before termination; forced exit cannot guarantee a recorded result. Preserve results when the popover/review closes; do not silently delete or promise automatic Undo. Explain manual Finder Put Back where available. Partial/selected-folder scans remain read-only and scans/chooser cannot overlap cleanup.
- Folder inventory is a separate, always-read-only scan scope. Retain one native chooser independently of the popover; only explicit confirmation starts a worker. Cancel leaves the previous scope/results untouched; delayed/revoked chooser responses cannot restart a stopped or discarded store. Display the actual selected path locally and an indeterminate progress indicator—do not invent a percentage. Rescan stays within the selected folder; returning to home cleanup is explicit. Never infer cleanup eligibility from a selected path or a forged safety label, and never persist/export the chosen scope. Hidden/package files and observed empty folders are counted; unavailable or redirected roots are not zeroes.
- The folder explorer retains the 100 largest successfully measured files and up to 256 first-discovered immediate-folder summaries; disclose omitted folders and retained-row search limits. Folder summaries are observed logical sums, not a guaranteed globally largest-folder list. Use native List selection keyed by path, All/Files/Folders filtering, and explicit Quick Look/Finder/Scan Folder controls. Space previews only from the list—not while typing search—and Return drills into a selected folder. Back rescans within the originally selected root (at most 64 scopes). Keep Quick Look native and user-initiated; validate current scope/path/type/symlink containment before preview/navigation, clear stale selection on new scans and disable actions during scans/chooser. Show optional file allocation as filesystem-reported, never space that can be reclaimed; directory allocation remains unavailable. Opening Disk does not automatically scan.
- Export is an explicit local save action, not background logging. Disclose the five-minute history window, exclude identities/addresses/paths, and distinguish snapshot/history timestamps in CSV.
- Motion is restrained and interruptible. Respect Reduce Motion; no animation of unrelated counters during page transitions. Opaque surfaces when Reduce Transparency is enabled.
- Bare topic/Back/chart/explorer keys leave native text editing/selection and assistive modifier chords alone. Route Back through the root policy, not an independent window-wide Escape accelerator. Conservatively reserve Caps Lock chords while VoiceOver is active. Command-F applies only to top-level CPU/Memory; ordinary text Copy remains Command-C and snapshot Copy Command-Shift-C.
- Every action works. No placeholder future-feature buttons. Destructive actions require a meaningful confirmation and report failure honestly. Assign the destructive alert's default Return action explicitly to Cancel, not the destructive button; retain native cancel-role Escape handling and verify actual OS behavior separately. Full failure text persists with explicit UUID-bound dismissal or a newer failure; success/background refresh must not erase it. Suppressed routine statuses are not queued/replayed. Announcements use an injected app-local accessibility client, only with VoiceOver active outside tests; no authorization request or new local notification channel. No automatic retries or extra telemetry timers.
- Power’s native Sources and limits disclosure describes actual collection scope, not live capability. Distinguish public macOS charge/settings/thermal APIs from hardware-dependent legacy battery registry details; battery temperature is not CPU/GPU temperature and reported input is not calibrated energy. GPU utilization/total memory, additional sensor/fan and accessory-battery backends are deferred from this release, not represented with future modules, sample charts, zeroes or enable controls. Disclosure expansion performs no device/permission probe and persists nothing. See `docs/HARDWARE_FEASIBILITY.md`.
- Unsupported/unavailable readings display an em dash or explicit explanation, never manufactured values. Memory headroom is an estimate, not the exact macOS pressure signal.

## Validation

`docs/ACCESSIBILITY.md` records focused native hardening and unperformed human sign-off. `docs/VALIDATION.md` separates automated evidence from checks requiring hardware or human interaction. Screenshots, if generated by the test harness, use deterministic fixture data and are not proof of live telemetry correctness.
